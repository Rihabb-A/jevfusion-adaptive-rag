# Data

Rules, no exceptions (from the course template):

- No personal data. No client data. No real users' information, ever.
- Public datasets, synthesized examples, or data the team generates itself.
- Everything in this folder except this file and the two dataset manifests
  is gitignored, so committing anything else here takes a deliberate
  `git add -f`.

This project uses two public datasets. Neither is committed: each is
downloaded from its official source by a script that records checksums
in a committed manifest, so anyone can rebuild the exact same data.

## SQuAD v1.1 (DAT reproduction and JevFusion)

- **Source:** the official SQuAD site,
  `https://rajpurkar.github.io/SQuAD-explorer/dataset/{dev,train}-v1.1.json`.
- **Script:** `python -m baseline.prepare_squad`, which samples whole
  articles with DAT's rule (paper §5.1, seed 42).
- **Sets:** `test` (13 dev-split articles, 621 paragraphs, 2,996
  questions) and `tune` (13 train-split articles, 623 paragraphs, 2,865
  questions), each question with exactly one gold paragraph.
- **Files:** `squad/raw/` (downloads), `squad/test/` and `squad/tune/`
  (`corpus.jsonl`, `queries.jsonl`).
- **Committed manifest:** [`squad_sample_manifest.json`](squad_sample_manifest.json)
  (seed, source checksums, sampled article titles, counts).

## BEIR NFCorpus (second dataset)

- **Source:** the official BEIR archive,
  `https://public.ukp.informatik.tu-darmstadt.de/thakur/BEIR/datasets/nfcorpus.zip`,
  MD5 `a89dba18a62ef92f7d323ec890a0d38d` (as listed in the BEIR README;
  checked on download).
- **Script:** `python -m extension.beir_data --dataset nfcorpus` (download,
  MD5 check, safe extraction, verification).
- **Content:** 3,633 medical documents (title + abstract), 3,237 queries;
  dev (324 queries) and test (323) with graded labels (1 = partially, 2 =
  highly relevant), on average 38 relevant documents per test query.
  Train is not used.
- **Files:** `nfcorpus/raw/` (archive and BEIR files).
- **Committed manifest:** [`nfcorpus_manifest.json`](nfcorpus_manifest.json)
  (source, hashes of every file, verification report).

## Caches (`cache/`, gitignored)

Regenerated by the scripts; kept so that re-running any evaluation costs
nothing.

| Path | Contents | Rebuilt by | API cost to rebuild |
|---|---|---|---:|
| `cache/{test,tune}_{bm25,dense}.npy` | SQuAD score matrices | `python -m baseline.retrieve --set ...` | ~$0.03 |
| `cache/embeddings_openai_text-embedding-3-large.npz` | SQuAD embeddings | same | (included) |
| `cache/judge/openai_gpt-4o-mini/test.jsonl` | DAT judge replies, SQuAD | `python -m baseline.dat_judge --set test` | ~$0.33 |
| `cache/jev/jev-1.13.0/{test,tune}_k{1,3}.jsonl` | Jev replies, SQuAD | `python -m extension.jev_judge ...` | ~$0.96 |
| `cache/nfcorpus/` | NFCorpus score matrices and embeddings | `python -m extension.nfcorpus retrieve ...` | ~$0.16 |
| `cache/judge/.../nfcorpus-*.jsonl`, `cache/jev/.../nfcorpus-*_k*.jsonl` | DAT and Jev replies, NFCorpus | `python -m extension.nfcorpus_judges ...` | ~$0.13 |

Cache files are named by dataset (`test`/`tune` for SQuAD, `nfcorpus-dev`/
`nfcorpus-test` for NFCorpus), so the two datasets can never overwrite
each other. Note: when the project folder is synced by OneDrive, appended
cache lines were twice lost on disk; every judge run therefore re-reads
its cache file and reports anything missing, and a re-run sends only the
missing requests.
